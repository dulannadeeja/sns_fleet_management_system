# app/src/modules/: business rules and database access (no React)

One folder per PRD module. Each change function checks the person's permission again inside its own transaction and writes the activity log there (TRD › Integrity rules). Rules in `app/AGENTS.md` apply here too.

- The activity log (`src/modules/activity/`, screen 15.5) is read only: no code changes or deletes an entry. Its page needs `seeActivityLog` (the admin by default); kinds come from the action's name (`person.*` is Settings, and so on); every action written to `audit_event` needs a sentence under `settings.log.actions` in both word files (`tests/log-words.test.ts`).
- Owner settings (`src/modules/settings/`, screens 15.2 and 15.7): the catalogue holds each setting's group, limits and starting value; `setting` keeps only values the owner changed. Only the owner changes them (`changeGroup` checks again in its transaction and logs `setting.change` with old and new); owner, admin and staff read them (`requireEmployee`). Settings are shared by the whole test database: a test changes only its own setting and puts it back.
- Cars (`src/modules/cars/`, screens 04.1–04.4, 04.8): a car's package and terms are dated versions in `vehicle_terms_version` (insert-only); a change adds one, so rentals keep theirs (AT-05). The commission is a partner term: seen with `seePartnerEarnings`, changed with `editPartners`; history and the log hide it from others. Pages use `AppFrame` and `railItems` (`src/app/rail.ts`). Starting packages (`packages.ts`, screen 04.6 at `/settings/packages`): a name, rates and models (a model can be in several; a new car picks one, `vehicle.starting_package_id`), and one `package_default` row; every employee reads them, `editCarsAndPackages` changes them (the commission default also `editPartners`); a model can be taken out (a package keeps one); logged `package.*` with old and new; packages are never removed. Tests add sample packages (names starting "Sample") for sample models only, never the real ones; nobody may add or edit packages under another prefix in tests.
- Car status (`cars/status.ts`, screen 04.5 at `/cars/[id]/status`): insert-only `vehicle_status_event`, the newest is the status (none is Available); `markCarUnavailable` sets Under repair or Unavailable, `markCarAvailable` marks available, the admin or owner role retires, only the owner brings a retired car back; `statusChoices` (`src/app/cars/status-choices.ts`) offers only what the person may do, and `changeStatus` checks again under the per-car lock. Logged `car.status`. Rented and Overdue come from rentals (Phase 2).
- Papers and photo (`cars/papers.ts`): insurance and licence expiry, next service date and km are four `vehicle` columns (the app may update only these and the partner link); every employee changes them at `/cars/[id]/papers`, logged `car.papers`. The catalogue photo is insert-only `vehicle_photo` (newest row wins; no file = removed), needs `editCarsAndPackages`, JPEG/PNG/WebP by its bytes up to 10 MB, private storage, shown only through `/cars/[id]/photo/[photoId]` to employees (not logged: not a customer document). `CarPicture` shows it or `VehicleImage`. A plain `<img>`: next/image would fetch it without the sign-in.
- Partners (`src/modules/partners/`, screens 11.1–11.3): a partner is a `user` (role partner) plus `partner_owner`; adding one links partner cars not yet linked (`linkCarToPartner` in the cars module, under the per-car lock) in one transaction. The commission and the costs the owner pays are partner terms. Pages need `seePartnerEarnings`; changes `editPartners`. The app role may set only a car's owner link and a partner's agreement date and bank account.
- Go-live checklist (`src/modules/golive/`, screen 01.3 at `/settings/golive`, owner only): ten items; `readChecklist` checks car dates (fleet = cars not retired), partner links and the authorised person by itself; the owner ticks the rest (`golive_tick`, insert-only, newest per item; unticking needs a reason; logged `golive.tick`/`untick`); items not built yet (`kind: 'later'`) never count as done. Going live itself is Phase 4. Ticks are shared by the test database: tests flip their own item and put it back.
- Customers (`src/modules/customers/`, screens 08.1–08.3): one NIC is one customer (AT-51); copies are private files (`src/storage/`: R2, or a private folder outside production), checked from their own bytes (`storage/kinds.ts`), insert-only rows; opening one goes only through `/customers/[id]/copies/[docId]`, which records it in `document_access` (AT-59). Everything needs `customerAccess`. Flags (`customers/flags.ts`, 08.5): `customer_flag` is insert-only except closing it once (a trigger), logged `customer.flagAdd`/`flagClose`; `warningsFor` is what New rental will read (Phase 2). The check before a rental (08.4, `/customers/[id]/check`) records `customer_go_ahead` (insert-only) only if the warnings shown still hold; a flag needs `proceedDespiteFlag`, an expired licence `overrideExpiredDocuments`.
